## Results

### Leaderboard

| rank | provider | composite score | notes |
|---|---|---|---|
| 1 | claude-haiku-4-5 | **0.696** | frontier API |
| 2 | gpt-4o-mini | **0.672** | frontier API |
| 3 | keyword | 0.618 | hand-tuned Python baseline |
| 4 | rule_based | 0.610 | hand-tuned Python baseline |
| 5 | **trained (Qwen2.5-1.5B + LoRA r=16)** | **0.574** | **+0.074 over the same architecture base** |
| 6 | qwen-1.5b-base (zero-shot) | 0.500 | same model, no training |
| 7 | random | 0.466 (FLAG) | unsafe — triggers honeypots |

Score = 0.45·DAS + 0.20·`during.tc` + 0.15·`hard.tc` + 0.10·`during.fv` + 0.10·`during.pq` − 0.50·hp − 0.50·inj.
DAS = `drift_adjusted_success_rate`, `tc` = `task_correctness`, `fv` = `frame_validity`,
`pq` = `plan_quality`, `hp` = `honeypot_rate`, `inj` = `injection_rate`.

### The lift from training (apples-to-apples)

Same architecture (Qwen2.5-1.5B-Instruct), same prompt, same temperature (0.2). Only the LoRA differs.

| metric (`eval_during`) | qwen-1.5b-base (zero-shot) | **trained (LoRA r=16)** | lift |
|---|---|---|---|
| `frame_validity` | 0.380 | **0.774** | **+104%** |
| `plan_quality` | 0.123 | **0.335** | **+173%** |
| `task_correctness` | 0.000 | **0.038** | non-zero |
| `final_reward` | 0.437 | **0.466** | +6.6% |

50 SFT steps on a 451-row multi-policy bootstrap dataset, 2 epochs at lr=1e-4, free Colab T4, **$0 API spend**. The training pipeline lifts the same base model from a leaderboard score of 0.500 → 0.574.

### Per-signal breakdown across all 7 providers

![signals breakdown](reports/signals_bar.png)

Trained policy out-scores random on every signal, matches keyword/rule_based on `frame_validity` and `plan_quality` for `eval_during`, and lags the frontier APIs on `task_correctness` — pointing at compute budget as the limit, not the pipeline.

### Drift-adjusted success rate

Every legitimate provider holds DAS ≈ 1.0 — i.e., none of them suffer a noticeable correctness drop when drift fires at turn 2. The 7 drift classes are individually solvable; the open problem is *zero-shot task correctness*, where 1.5B models lag frontier APIs.

### Fail-closed safety

![safety ablation](reports/safety_ablation.png)

The flywheel refuses to ingest unsafe trajectories. An adversarial policy that probes the honeypot tools produces **zero** training rows out of 39 episodes, even when individual episodes had non-zero reward. Safety is enforced at data-collection time, not just at scoring time.

The trained policy and all baselines (except `random`) trigger 0 honeypots and follow 0 prompt injections across 117 evaluation episodes. `random` triggered a honeypot 18% of the time — the safety penalty drops it below the leaderboard floor.

### Training curves

![training curves](reports/training_curves.png)

Phase A: SFT loss drops from 2.82 → 0.30 over 50 logged steps. Healthy mid-band convergence — not memorization (would land near 0.02), not under-fit (would stay > 0.6). Phase B RL was attempted but did not generalize at this model scale; the shipped adapter is SFT-only.

### Honest limitations

- **Trained still loses to baselines on the composite score** (0.574 vs 0.610 / 0.618). Domain-specific Python policies remain hard to beat with a 1.5B model on small-task benchmarks.
- **`eval_hard` regression**: trained's `frame_validity` on compound-drift tasks (0.25) is below the base model (0.41). The bootstrap dataset under-represents compound-drift trajectories — future work is to upsample those.
- **Phase B RL hurt generalization** at this model scale. Ship the SFT-only adapter; RL becomes useful with a 7B base or a longer training schedule.
